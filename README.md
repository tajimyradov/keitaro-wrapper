# Keitaro wrapper (Adrobot, тестовое)

Обёртка над Keitaro Admin API: FastAPI + SQLAlchemy 2 + Alembic, фронт — один `frontend/index.html` на чистом JS (без сборки).

1. **Создаватор кампаний**: название + гео (`MX,AU,RO`, можно несколько) + оффер (автокомплит) + домен/группа/источник.
   Создаёт кампанию с ротацией «по позиции», моделью затрат CPC (0 USD) и двумя потоками:
   - поток 1: фильтр «страны: принимать» → редирект на `https://google.com`;
   - поток 2: без фильтров (весь остальной трафик) → выбранный оффер, доля 100%.
2. **Редактор офферов** (логика из видео ТЗ): локальный слепок потоков в БД, правки накапливаются и уходят в Keitaro только по кнопке «Опубликовать».

## Требования
Python 3.11+. Node не нужен.

## Запуск
```bash
cp .env.example .env        # заполните KEITARO_API_KEY и CAMPAIGN_PREFIX
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
alembic upgrade head        # создаёт таблицы журнала в app.db
uvicorn app.main:app --reload
```
Откройте http://127.0.0.1:8000. Swagger обёртки: `/docs`.

### Переменные окружения
| Переменная | Описание |
|---|---|
| `KEITARO_URL` | адрес Keitaro без `/admin` (по умолчанию `https://tlgk.host`) |
| `KEITARO_API_KEY` | ключ: профиль в админке → «API ключи» |
| `CAMPAIGN_PREFIX` | префикс кампаний, например `test_ivanov_` |
| `DATABASE_URL` | по умолчанию SQLite `sqlite:///./app.db`; для Postgres нужен драйвер (psycopg) |

### Миграции
```bash
alembic upgrade head        # применить
alembic downgrade base      # откатить
alembic revision --autogenerate -m "msg"   # после изменения models.py
```
Все команды `alembic` запускаются из папки `backend/`.

### Тесты
```bash
cd backend && python -m pytest -q
```
Тесты идут на фейковом Keitaro: доли, валидация гео, создание с откатом, добавление/удаление офферов, защита чужих кампаний.

## Как работает редактор
- **Получить потоки**: тянет потоки кампании из Keitaro. Потоки без офферов (редиректы) показываются только названием, их содержимое не разбирается и менять их нельзя.
- **Добавить оффер**: поиск по офферам Keitaro (автокомплит). Доли сразу пересчитываются (4 оффера = по 25%), поток становится жёлтым (не опубликован). В Keitaro при этом ничего не меняется, локальные правки переживают обновление страницы.
- **Опубликовать**: отправляет офферы и доли потока в Keitaro, поток снова белый.
- **Отмена**: сбрасывает неопубликованные правки. Добавленные привязки удаляются, удалённые и изменённые доли возвращаются к состоянию в Keitaro.
- **Удалить**: оффер серый, доля 0%, поток жёлтый. После публикации оффера в Keitaro нет, но у нас он остаётся в архиве (серый) с кнопкой **«Вернуть»**.
- **Синхронизация**: если оффер удалили прямо в Keitaro, то после «Получить потоки» он станет серым (removed), как будто удалён из обёртки, и его можно вернуть. Неопубликованные правки при этом сбрасываются.
- **Закрепление веса**: у закреплённого оффера доля не меняется при добавлении, удалении и возврате других офферов (в том числе вернётся тем же весом). Остаток до 100% делится поровну между незакреплёнными, остаток от деления получают первые офферы. Закрепление хранится только локально.

## API обёртки
| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/meta` | домены, группы, источники, префикс |
| GET | `/api/offers?q=` | поиск офферов (по названию или ID) |
| POST | `/api/campaigns` | создать кампанию |
| GET | `/api/campaigns` | кампании с вашим префиксом |
| GET | `/api/campaigns/{id}/streams` | локальное состояние потоков |
| POST | `/api/campaigns/{id}/fetch` | синхронизация с Keitaro |
| POST | `/api/campaigns/{id}/streams/{sid}/offers` | добавить оффер `{offer_id}` |
| DELETE | `/api/campaigns/{id}/streams/{sid}/offers/{offer_id}` | удалить оффер |
| POST | `.../offers/{offer_id}/restore` | вернуть удалённый оффер |
| PUT | `.../offers/{offer_id}/pin` | закрепить/открепить вес `{pinned}` |
| POST | `/api/campaigns/{id}/streams/{sid}/push` | опубликовать в Keitaro |
| POST | `/api/campaigns/{id}/streams/{sid}/cancel` | отменить неопубликованное |

`sid` — ID потока в Keitaro.

## Отладка формата API
`GET /api/debug/campaigns/{id}/streams` отдаёт сырой ответ Keitaro по потокам кампании (только с вашим префиксом). Удобно, если поля потоков отличаются от ожидаемых.

## Локальная БД
`campaign_log` (созданные кампании), `stream` и `stream_offer` (слепок потоков, желаемое состояние и то, что сейчас в Keitaro), `action_log` (журнал действий).

## Допущения
- К названию автоматически добавляется `CAMPAIGN_PREFIX`; редактор работает только с кампаниями с этим префиксом.
- Публикация требует: хотя бы один активный оффер, сумма долей ровно 100%, у каждого доля больше 0. Иначе понятная ошибка (например, если закреплённые веса занимают всё место).
- Оффер, добавленный и удалённый до публикации, просто исчезает (в архив попадают только опубликованные).
- Если создание второго потока упало, кампания удаляется (откат).
- Названия полей API (`schema: "landings"`, `cost_type`, формат фильтра) написаны по документации Keitaro 10.x; сверьте со Swagger инстанса.
